Why B+ Trees and Hash Indexes?

When a table has millions of rows, a Full Table Scan must inspect every single record in memory ($O(n)$ time). This database engine uses two complementary index structures to eliminate linear scans:

Operation Full Scan Hash Index B+ Tree
Point Lookup (WHERE col = X) O(n) O(1) avg O(log n)
Range Scan (BETWEEN A AND B) O(n) ✗ Not Supported O(log n + k)
Insert O(1) O(1) avg O(log n)
Delete O(n) + O(1) O(1) avg O(log n)

The Linked Leaf Chain Secret

Notice the horizontal arrows connecting leaf nodes in the B+ Tree Index tab. In a traditional B-Tree, range scans require recursive tree traversals up and down internal nodes. In a B+ Tree, all data is in the leaves, and every leaf maintains a next pointer to its right neighbor. Once the starting point is found in $O(\log n)$ steps, the engine traverses the linked list directly in $O(k)$ time!
